# 구독자 성장 계획 (2026-09-21)

> 운영자 정의: **"가입자 수가 아니라 구독자 수가 제일 중요하다."**
> 이 문서는 그 정의를 실행 가능한 단계로 옮긴 것이다.
> 비전은 `memory/project_brand_vision_art_meets_makeup.md`, 우선순위 기준은 북극성(글로벌 유입·수익).

---

## 0. 용어를 먼저 고정한다

| 용어 | 정의 | 현재 실측 |
|---|---|---|
| 방문자 | 한 번 왔다 가는 사람 | (GA4) |
| **가입자** | 계정을 만든 사람 | **약 30명** (메일 수신 대상 26명 = 인증 완료·제외 후) |
| **구독자** | ①우리가 다시 말 걸 수 있고 ②그 말에 반응하는 사람 | **모름 — 측정 장치가 없다** |

**구독자 = 채널 보유 × 반응.** 둘 중 하나라도 0이면 구독자가 아니다.

현재 채널은 셋뿐이고 상태는 이렇다:

| 채널 | 규모 | 반응 측정 |
|---|---|---|
| 이메일 (주간 다이제스트) | 26명 | ❌ 열람·클릭 추적 코드 없음 |
| 앱 푸시 | **1대** (운영자 폰) | 앱 미출시 |
| 소셜 (TikTok @kissinskin) | 미확인 | — |

→ **우리는 구독자가 몇 명인지 모른다.** 이것이 0순위 문제다.

---

## 1. 지금 구조의 결함 3가지 (코드 실측, 2026-09-21)

### ① 무료 도구는 아무것도 남기지 않는다
퍼스널컬러·얼굴형·메이크업MBTI·향수타입 4종은 **로그인 없이** 전부 동작한다.
트래픽 유입 장치로는 옳다. 그런데 **끝나면 그걸로 끝이다** — 이름도, 이메일도, 발자국도 안 남는다.
유입의 대부분이 여기로 들어오는데 회수 장치가 0이다.

### ② 마이페이지에 돌아올 이유가 없다
현재 마이페이지 전체 구성: 이메일 표시 / 로그인 방식 / 크레딧 잔액 / 결제 내역 / 비밀번호 변경 / 회원 탈퇴.
**이건 "내 공간"이 아니라 계정 설정 화면이다.** 가입한 사람이 다시 열어볼 이유가 한 줄도 없다.

### ③ 결과물이 서버에 안 쌓인다
- 무료 도구 4종 + beauty-dna 결과 → **전부 `localStorage`**
  → 폰을 바꾸거나 브라우저를 지우면 **전부 소멸**. 계정과 아무 관계가 없다.
- `results` / `shared_results` 테이블은 **이미 존재**하는데, 쓰는 곳이 `shareResult.ts` 경유
  AI 메이크업 결과와 ResultPage뿐이다. (AnalysisApp은 죽은 코드)

**결론: 지금은 가입자를 늘려도 새는 양동이다.** 벽을 높이기 전에 바닥을 막아야 한다.

---

## 2. ⭐ 한 기능이 세 문제를 동시에 푼다

**"내 뷰티 기록" — 진단 결과를 계정에 저장하고 쌓아 보여주는 것.**

| 푸는 문제 | 어떻게 |
|---|---|
| **가입할 이유** | "저장하려면 로그인" — 사람들이 유일하게 납득하는 로그인 벽 |
| **돌아올 이유** | 기록이 쌓일수록 지우기 아까워진다 (= 구독자화) |
| **iOS 심사 통과** | 애플 4.2는 네이티브 화면 + 오프라인 동작을 요구한다 (§5 참조) |

세 개를 따로 풀면 세 배가 들고, 이건 하나로 풀린다. **그래서 이게 1순위다.**

## 3. 단계 전략

### Stage 0 — 측정 장치 (지금 당장, 반나절)
**없으면 이후 모든 판단이 추측이 된다.**

1. **메일 열람·클릭 추적 켜기** — Resend에 태그를 붙여 회차별 열람률/클릭률을 본다.
   → 이 숫자가 나오는 순간 "구독자 26명"이 실제로 몇 명인지 처음 알게 된다.
2. **GA4 가입 퍼널 이벤트** — `도구 완료 → 저장 시도 → 가입 화면 → 가입 완료` 4단계.
   지금은 어디서 새는지 모른 채 고치고 있다.

**성공 기준:** 다음 주 발송 후 "열람률 N%"를 숫자로 말할 수 있다.

---

### Stage 1 — 바닥 막기 (가장 크게, 가장 먼저)
**목표: 방문자가 흔적을 남기게. 가입이 손해가 아니라 이득이 되게.**

1. **무료 도구 결과를 서버에 저장** (`results` 테이블 재사용 — 새로 만들 필요 없다)
   - 비로그인: 지금처럼 localStorage에 두되, 결과 화면에 **"이 결과 저장하기"**
   - 로그인: 계정에 저장 + 기존 localStorage 결과를 **가입 즉시 계정으로 승계**
   - ⚠️ 도구 자체에는 절대 로그인 벽을 세우지 않는다. **트래픽이 전부 죽는다.**
2. **마이페이지 → "내 뷰티 기록" 재설계**
   - 내 퍼스널컬러 / 얼굴형 / MBTI / 향수 / beauty-dna / AI 메이크업 룩이 한 화면에
   - 비어 있는 칸은 **"아직 안 한 진단"으로 표시** → 다음 행동을 유도 (= 재방문 이유)
   - 크레딧·결제·탈퇴는 하단 '설정'으로 강등
3. **결과 카드 공유에 되돌아오는 링크** — 공유 이미지·링크가 사이트로 다시 데려오게

**성공 기준:** 도구 완료자 중 저장 시도율, 저장 시도자 중 가입 완료율이 GA4에 찍힌다.

---

### Stage 2 — 채널 확보 (앱 출시) → §5 상세
**목표: 말 걸 수 있는 통로를 이메일 하나에서 둘로.**

근거 (2026 벤치마크):
- **Android 푸시 옵트인 91.1%** vs iOS 43.9% → **안드로이드 먼저가 수치로도 맞다**
- **첫 90일에 푸시를 1회 이상 받은 사용자의 리텐션이 3배**
- ⚠️ **주 6회 초과 푸시 = 30일 내 삭제 확률 3.4배** → 우리 주 1회 발행 리듬이 정확히 맞는 빈도다

---

### Stage 3 — 창작자 (구독자가 쌓인 뒤)
- 저장된 룩에 "공개" 옵션 → 갤러리
- 잘하는 사용자를 **이름 걸고 노출** (아티스트 승격)
- Glossier가 댓글 300개로 제품을 정한 그 자리가 여기다

### Stage 4 — 상품 / 오프라인
- 갤러리 상위 룩 → 한정판·컬래버 → PB
- 오프라인은 **매장이 아니라 무대**로 (Aesop: 400개 매장을 전부 다르게)
- 무신사도 커뮤니티 → PB → 오프라인 순서였고 **20년** 걸렸다

## 4. 우선순위 — 제일 먼저 고칠 것

| 순위 | 할 일 | 크기 | 왜 지금 |

## 5. 앱 출시 전략

### 5-1. 현재 상태 (`kisskin-app/`, Expo SDK 54 WebView 래퍼)
빌드 #7까지 완료. 카메라·저장·공유·구글로그인·푸시·외부브라우저 결제 분기 **코드 전부 완료**.
FCM 연결 완료, 실기기 푸시 수신 검증 완료.

### 5-2. Android (Play Store) — 남은 것만
1. **빌드 #7 실기기 재검증** — ④ 카메라/저장/공유 브릿지 (빌드 #6에서 테스트 중 중단됨)
2. **Play Console 등록 $25** — 운영자 직접. **신분 확인에 시간이 걸리니 오늘 걸어두는 게 좋다**
3. **스토어 등록 자료** (Claude 준비 가능): 설명문 ko/en, 스크린샷 규격, 개인정보처리방침 링크
4. **production AAB 빌드 → 심사 제출**
5. 출시 후: 푸시 **주 1회**, 화요일 발행 콘텐츠에 맞춰 발송 (기존 `send-push.yml` 그대로 사용)

⚠️ 결제: Play는 앱 내 디지털 상품에 Play Billing을 요구한다. 외부 브라우저 분기는 이미 완료(`36b9049`).
웹에서 산 크레딧을 앱에서 쓰는 건 허용된다(넷플릭스 방식).

### 5-3. iOS — 4.2 리젝을 피하는 조건
애플은 **순수 웹뷰 래퍼를 가이드라인 4.2(최소 기능)로 리젝**한다.
조사 결과 핵심은 이것이다: **"화면을 더 만드는 것으로는 안 통한다. 네이티브 통합이 필요하다."**

통과한 앱들의 공통 요소:
- 주요 콘텐츠를 **네이티브 UI로 렌더링** (데이터는 API에서 와도 됨)
- **오프라인에서도 쓸모 있을 것** — 심사자가 비행기 모드를 켠다
- 푸시 / 카메라 등 **기기 통합**

우리에게 가장 싼 조합:
| 요구사항 | 우리 대응 | 비용 |
|---|---|---|
| 네이티브 화면 | **"내 뷰티 기록"을 네이티브로** (P1에서 이미 만드는 것) | 추가 소량 |
| 오프라인 동작 | 저장된 내 기록을 로컬 캐시에서 표시 | 소 |
| 기기 통합 | 카메라·푸시 **이미 있음** | 0 |

→ **P1(내 뷰티 기록)이 iOS 심사 통과의 전제조건이다.** 순서를 지키면 공짜로 따라온다.

비용: Apple Developer $99/년 + APNs 설정. **안드로이드 안정화 후.**

## 6. 하지 말 것

- ❌ **무료 도구에 로그인 벽** — 유입의 대부분이 거기로 온다. 가입자 몇 명 얻고 트래픽을 잃는다.
- ❌ **저장 기능 없이 앱 먼저 출시** — 4.2 리젝 + 열 이유 없는 빈 앱
- ❌ **푸시 남발** — 주 6회 넘으면 삭제율 3.4배. 주 1회를 지킨다.
- ❌ **가입자 수를 성과로 보고하기** — 열람·재방문이 없으면 숫자일 뿐이다.
